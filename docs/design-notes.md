# 設計ノート — なぜこの仕様なのか

## 発端

市販の左手デバイス(Mouserpad v2、¥7,590)を検討したが、実際のプレイで致命的な問題があった:

1. **レレレ中のダッシュ暴発**
   Apex のホライゾンで、グラビティリフトで浮きながらバッテリーを巻き、
   弾避けに左右移動(レレレ)を混ぜると、スティックが前方向を含んだ瞬間に
   オートダッシュ(Shift)が乗って回復がキャンセルされる。
2. **前進しながらの回復も不可**
   回復しつつ前に進みたいとき、スティックを倒しすぎるとオートダッシュが
   発動して同じくキャンセル。つまり「回復中はスティックを慎重に倒す」
   ことをプレイヤー側が強いられる。

市販品はこの挙動を変更できない。→ 自作すれば設計レベルで直せる。

## 主要な設計判断

### D1. ダッシュは独立した物理ボタン(デフォルト)

- スティック入力とスプリントを完全に分離する。
  スティックをどれだけ・どの方向に倒しても Shift は乗らない。
- 誤爆源を「賢い制御で抑える」のではなく「構造的に消す」。
  デバッグが楽で、挙動が予測可能。

### D2. オートダッシュはオプションとして残す(比較・他ゲー用)

- プロファイル `auto-dash` で有効化できる。
- ただし市販品との差別化として:
  - **発動閾値を高めに設定可能**(threshold 0.92〜)
  - **コンテキスト抑制**: 回復キー(4)を押した直後 N 秒間は
    オートダッシュを無効化。バッテ5秒/医療キット8秒に合わせて調整。

### D3. プロファイルは本体フラッシュに保存

- `microcontroller.nvm` に選択中インデックスを保存。
- どの PC に挿しても同じ挙動。ドライバ・常駐ソフト不要
  (= 販売時のサポートコストが低い)。

### D4. 有線 USB 固定

- 無線化すると技適(電波法)が必要で個人販売には非現実的。
- 有線 USB バスパワーなら PSE(電気用品安全法)も対象外。

### D5. ファームウェアは完全自作(CircuitPython)

- GPL 系の既製ファームウェアを流用するとソース公開義務が絡む。
  販売を見据えて MIT でクリーンに保つ。
- 挙動の芯(8方向判定、ヒステリシス、抑制ロジック)は 200 行程度で書ける。

### D6. 筐体はオリジナル形状

- Mouserpad v2 の形状をそのまま複製して販売すると
  不正競争防止法(形態模倣、発売から3年)に触れるおそれ。
- どのみち自分の手に合わせてグリップを再設計するので、
  パラメトリックモデル(case.scad)で角度・配置を数値管理する。

## 市販品(Mouserpad v2)レビュー分析 — 弱点と本機での対策

2026-07 時点の Amazon レビューから抽出。★4.1(47件)でもこれだけ不満が残っている
= 改善版を出せば刺さる余地が大きい。

| # | 市販品の弱点(レビューより) | 本機での対策 |
|---|---|---|
| 1 | **ESCキーが無い**。ゲーム内で再割当できず、ゲーム中はPowerToys等も無効。頻繁にキーボードへ手を伸ばす羽目に | **ESC物理ボタンを追加**(config で `top_esc` として定義済み)。キーマップ自由なので任意キーにも変更可 |
| 2 | **キー割当が固定**(変更不可)。左Shift や ESC が割当できずゲームによっては使い物にならない | ファームウェアの config でフルリマップ可能。プロファイル切替も対応済み |
| 3 | **ボタンの押下感がふんわり**、カチッと感なし。強く押さないと反応せず、二度押しでしのぐ人も。分解したら半田不良の個体もあり | メカニカルスイッチ(Kailh choc 等)+ちゃんとした半田付け。試作段階から導通チェックを工程に入れる |
| 4 | **ボタン数が足りない**(押しにくい位置でもいいから3つ増やして欲しいという要望) | 予備ボタン2個分のピンを config に確保(`spare_1`/`spare_2`)。筐体側で増設位置を試作しながら決める |
| 5 | **小指・薬指が窮屈**。ボタン操作しない指で握り続けるため手首の筋が痛む。「親指側を細く、薬指小指側を太く」という具体的提案あり | `case.scad` のグリップを上下で太さ可変に(親指側細め・下側太め)。パラメトリックなので試作で追い込める |
| 6 | **机の手前端で使うと手が浮いて小指側の掌に荷重集中**、痛み・痺れ。ジェルクッションが欲しいという声 | パームレスト部を広めに設計+底面にゲルパッド貼付を標準化。設置姿勢(机上前提)をドキュメント化 |
| 7 | **正面最下段の1・2ボタンが握りを浮かせないと届かない**=ほぼ死にボタン | ボタン配置は`button_layout`で座標管理。届かない位置には置かない。試作で親指可動域を実測してから確定 |
| 8 | **スティックがシビア**。少し倒しただけで全開扱い、歩ける範囲が1mm程度。乗り物操縦では曲がりすぎる。オートダッシュ常時発動で余計に酷い | デッドゾーン・発動閾値を config で調整可能。オートダッシュはデフォルトOFF+コンテキスト抑制。将来的にはゲームパッド軸出力プロファイルも検討(ロードマップ参照) |
| 9 | **MicroUSBコネクタが3.5ヶ月で破損**(役立った47人=最重要レビュー)。基板を筐体と面一に置いたせいでコネクタ金属部が露出し、奥まで挿そうとグリグリやって壊れる | **コネクタを筐体内に沈めない設計ミスを回避**: Pico本体は内部固定し、パネルマウントUSB-C延長ケーブルで筐体面に出す。ストレインリリーフ付き。修理性も上がる |
| 10 | **スティックの首回り強度が弱い**、2週間で擦れ粉 | ホールセンサー式の交換モジュール前提。開口部エッジを面取りし、モジュール交換をネジ止め式に |
| 11 | 背面の交換パーツが付属するが**説明書に一切記載なし** | 説明書(README)に全付属品と用途を明記。販売時はここが信頼の差になる |

レビュー全体の温度感: 「コンセプトは唯一無二、品質は値段なり、改善版を出してくれ」。
つまり**市場は改善版を待っている**。AZERON Cyborg(高価格帯)との間に価格帯の空白もある。

## 販売までのロードマップ

1. **自分用1号機**: PLA試作でグリップ形状を確定 → PETG で常用機
2. **公開**: SNS で反応を見る(写真+ダッシュ分離のデモ動画)
3. **販売版設計**: QC しやすい分割、キーキャップ色替えでカラバリ、
   Raspberry Pi 財団の VID/PID 割当を申請
4. **販路**: BOOTH から開始 → 反応次第で Makuake 等のクラファン
